# 자체 개발 QA 100문항 검증

## 목적과 구성

프로젝트가 기존 질문 문장만 통과하는지 확인하기 위해 기존 질문과 완전히 일치하지 않는
신규 질문 100개를 직접 작성했다. 형식은 요청에 맞춰 `close` 50개와 `open` 50개로
고정했다.

| 형식 | 건수 | 검증 내용 |
|---|---:|---|
| `close` | 50 | 재무 수치, 전년동기 증감액·증가율, 기업 간 차이, 영업이익률, 투자 집행률, 계약 비중·최신 계약상대 |
| `open` | 50 | 사업·제품·서비스 포트폴리오, 산업별 사업 설명, 전략 변화, 분기·사업보고서 비교 |

질문은 새로 작성하되 정답을 실행 결과에 맞춰 바꾸지 않도록, 이미 원문 대조를 마친
strong gold·cross-industry·manual QA의 기대값을 `source_case_id`로 상속한다.
생성기는 100개 고유 문장, 기존 질문과의 완전 일치 0개, `close/open` 각 50개를
검사한다. 각 materialized 문항에는 기대 수치와 허용오차, 단위, 연결/별도 scope,
기간, 필수 접수번호, 필수 근거·답변 문자열이 포함된다.

## 직접 실행과 개선 과정

전체 `outputs/disclosures.db`에서 외부 LLM을 끈 결정론 모드(`use_llm=False`)로 세 차례
전수 실행했다.

| 단계 | 결과 | 확인한 내용 |
|---|---:|---|
| 최초 기준선 | 60/100 | `close` 41/50, `open` 19/50 |
| 질의 분석 개선 후 | 99/100 | `close` 49/50, `open` 50/50 |
| 문항 기간 명시 보정 후 | 100/100 | `close` 50/50, `open` 50/50 |

최초 실패를 실제 답변과 check 단위로 확인해 다음을 개선했다.

- 서술형의 `제품군`, `사업 구성`, `성장 전략`, `R&D 초점` 등을
  `business_overview` 전용 경로로 보낸다. 단순 재무 수치 설명은 재무 경로에 남긴다.
- `증가액과 증가율`, `전년 같은 분기`, `격차`, `얼마 더 큰` 표현을 계산 질의로
  정규화한다.
- `계약금액/최근매출액 비중`과 `최신 계약상대방` 표현을 정형 계약·정정 체인 경로로
  보낸다.
- `포스코홀딩스`를 `POSCO홀딩스`의 안전한 별칭으로 추가했다.
- 짧은 별칭 `현차`가 “표현 차이” 안에서 오검출되는 문제를 회사명 경계 매칭으로
  제거하면서 `삼성 전자` 같은 공백 입력은 계속 허용한다.
- 사용자가 표준 지표의 별칭을 쓴 경우 `영업수익(매출액)`처럼 사용자 표현과 표준명을
  함께 표시한다.

99번째 통과 후 남은 한 문항은 질문에 연도를 쓰지 않고 2025년 기대 조건을 붙인
문항 설계 오류였다. 질문에 기간을 명시해 정답 조건과 일치시켰으며, 기대값을 느슨하게
바꾸지는 않았다.

## 재현 방법과 최종 회귀 결과

```bash
make eval-development DB=outputs/disclosures.db
```

이 명령은 `eval/build_development_qa_100.py`로 질문셋을 결정론적으로 재생성한 다음
`eval/evaluate_manual_qa.py`로 100개를 모두 실행한다.

- 자체 개발 QA: 100/100 (`close` 50/50, `open` 50/50)
- strong gold: 50/50
- 산업 확장·기간/출처 충돌·정보 한계: 40/40
- 운영 경계: 29/29
- 단위·통합 테스트: 117/117
- 강화형 실제 API QA: 100/100 (`close` 50/50, `open` 50/50)

상세 질문은 `eval/development_qa_100_questions.jsonl`, 질문별 실제 답변과 모든 check는
`eval/development_qa_100_results.json`에 보존한다.
