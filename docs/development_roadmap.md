# 프로젝트 발전 로드맵

2026-09-04 기준 단위·통합 131/131과 기존 평가를 통과했고, 아래 1~4단계 QA도
실제 HTTP 기준 각각 100/100, 합계 400/400을 완료했다. 상세 기준선·개선·최종 결과는
`docs/roadmap_qa_400_validation.md`에 기록한다.

## 1. 평가 범위 확장

100문항 단위의 다음 독립 골드셋을 추가했다.

1. 기간·정정·lifecycle 100문항: 원 공시/정정/현재 유효 값, 계약 체결–변경–해지,
   계획 금액과 실제 완료 금액을 구분한다.
2. 복합계산 100문항: 두 기업·두 기간·복수 지표, 증감액과 증감률, 단위·통화·scope
   불일치 시 안전한 거절을 검사한다.
3. 답변불가·보안 100문항: 코퍼스 밖 정보, 최신 주가, 근거 없는 예측, prompt injection,
   개인정보·secret 요청을 검사한다.
4. 장문·오타·구어체 100문항: 잘못된 띄어쓰기, 초성/약칭, 혼합 한영 표기와 불필요한
   배경 설명 속에서도 핵심 slot을 복원하는지 검사한다.

각 세트의 최초 기준선, 실패 원인, 코드 수정, 최종 결과를 별도 결과 JSON과 통합 검증 문서로 남겼다.

## 2. 평가 지표 고도화

단순 통과율 외에 다음 지표를 CI 품질 게이트로 사용한다.

- 답변 정확도: 수치·단위·기간·scope·정정 상태
- 근거 정확도: 답변 claim이 실제 citation에 존재하는 비율
- citation 정밀도: 답변에 사용하지 않은 문서가 인용되지 않는 비율
- 일관성: 의미 동일 질문쌍의 plan·답·인용 문서 일치율
- 거절 정확도: 답변 가능한 질문을 거절하거나 답변 불가능한 질문을 추측하지 않는 비율
- 성능: p50/p95/p99 지연시간, timeout·5xx 비율, 동시 요청 처리량

PR마다 빠른 단위 테스트와 핵심 골드셋을 실행하고, main 병합 전에는 전체 HTTP 평가를
실행하도록 GitHub Actions를 구성한다.

## 3. 데이터와 검색

- 신규 공시 증분 수집, 정정공시 version graph 갱신, 실패 문서 재처리를 자동화한다.
- 문서·표·cell locator를 샘플링해 원문 대조 감사를 정기 실행한다.
- FTS 후보 검색 뒤 산업·문서 유형별 reranker를 적용하고, 효과는 고정 골드셋의
  정확도와 지연시간으로 비교한다.
- 한 답변이 사용하는 문서 범위를 명시적으로 제한해 서로 다른 분기·정정 버전의 근거가
  섞이지 않도록 한다.

## 4. HyperCLOVA X 실연동

1. NCP secret manager 또는 배포 환경변수로 endpoint·API key를 주입한다.
2. 결정론 수치·계산 경로는 유지하고, 모델은 공시 근거를 자연어로 압축하는 단계에만 쓴다.
3. 생성 답변의 숫자·회사·기간·citation을 guardrail로 재검증하고 실패 시 결정론 답변으로
   fallback한다.
4. `use_llm=false/true`를 같은 질문셋으로 A/B 평가해 정확도 저하 없이 가독성이 좋아지는지
   확인한다.

완료 기준은 실연동 100문항에서 citation 누락 0건, 근거 없는 숫자 0건, fallback 성공률
100%, secret 노출 0건이다.

## 5. API·운영

- 기존 `GET /answer`와 함께 요청 JSON을 받는 versioned `POST /api/v1/answer`를 제공한다.
- request ID, 문서 버전, 모델 버전, 지연시간, fallback 사유를 구조화 로그로 남긴다.
- readiness/liveness, timeout, rate limit, 최대 질문 길이, 동시성 제한을 배포 환경에서 검증한다.
- 평가 결과를 대시보드화하고 실패 문항을 자동으로 회귀셋 후보에 추가한다.

## 권장 다음 작업

1~4단계 정확도 확장은 완료했다. 다음 우선순위는 복합 계산 HTTP 지연을 줄이기 위한
사업 프로필 사전 계산·캐시, HyperCLOVA X 실연동 100문항 A/B, 배포 환경의 timeout·rate
limit·p95/p99 성능 검증이다.
