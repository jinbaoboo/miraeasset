# 자체 생성 Close/Open QA 평가 및 개선 결과

## 평가 범위

- 평가셋: `eval/generated_qa_questions.jsonl`
- 질문 수: 20개
  - Close 10개: 단일 수치, 파생 비율, 전년 동기 증감액·증감률, 기업 간 차이,
    계약 비율, 투자계획, 정정 후 현재 유효 값
  - Open 10개: 주요 사업·제품·서비스, 특정 부문 현황, 산업별 사업 설명,
    연도/보고서 유형별 사업 변화
- 실행 방식: `DisclosureAgent(...).answer(..., use_llm=False)`
- 검증 기준: 필수 정답값·단위·기간·scope·회사·질의 유형·금지 표현·Context 완전성·답변 내 접수번호

## 기준선 결과

최초 실행 결과는 3/20 통과였다.

| 유형 | 통과 | 실패 | 주요 원인 |
|---|---:|---:|---|
| Close | 3 | 7 | 복합 계산, 기업 간 차이, 계약 비율, 현재 유효 값 표현 인식 부족 |
| Open | 0 | 10 | 전용 답변기 부재로 첫 검색 결과를 그대로 출력 |

답변을 직접 읽어 확인한 추가 문제는 다음과 같았다.

- KT 전체 사업 질문에 계열사 음원 가격표가 선택됨
- NC 주요 제품 질문에 표 제목과 단위만 출력됨
- 사업 개요보다 가격표·세부표가 우선되는 경우가 있음
- NAVER 사업 변화에 자동차 전용 `하이브리드`, `현지생산·현지화` 키워드가 오탐됨
- 전년 동기 질문이 증가액과 증가율을 동시에 제공하지 못함
- 두 기업의 차이 계산 결과가 없거나 원 단위로 과도하게 환산됨
- 파생 비율 답변의 계산 입력 중 일부가 최종 Context에서 빠짐
- 질문은 1분기인데 답변에는 연도 또는 3월만 표시되는 경우가 있음

## 반영한 개선

### 질의 분석

- `주력 제품`, `대표 제품`, `사업 현황과 전략`, `플랫폼과 콘텐츠 사업` 표현을
  `business_overview`로 분류
- 연도 간 사업 전략 비교와 같은 연도 사업보고서/분기보고서 비교를
  `business_change`로 분류
- `현재 유효한 계약상대`를 정정 체인 조회로 분류
- `공급계약 금액은 최근매출액의 몇 퍼센트`를 `contract_ratio`로 분류
- 전년 동기의 `금액과 비율` 동시 요구를 `growth_amount_and_rate` 계산으로 분류

### Close 답변

- 파생 비율의 모든 입력 셀을 Context에 우선 포함
- 연결/별도와 분기 표현을 계산 답변에 유지
- 전년 동기 증가액과 증가율을 함께 계산
- 두 기업의 동일 기간·scope·통화 확인 후 차이와 대소관계를 계산
- 동일한 공시 단위끼리는 백만원 등의 원 단위를 유지하고 불필요한 원 환산을 피함
- 이벤트 비율 필드에 `%`를 복원하고 사용자 질문의 지표명으로 출력

### Open 답변

- `II. 사업의 내용 > 1. 사업의 개요`를 최우선 근거로 사용
- `2. 주요 제품 및 서비스`를 보충 근거로 사용
- 가격변동표나 일부 계열사 서비스가 회사 전체 사업 설명을 대체하지 않게 함
- 출처 머리말 반복을 제거하고 문장 경계에서 발췌 길이를 제한
- 차량부문 질문에서는 차량부문 문맥만 유지
- 회사 산업이 자동차가 아니면 자동차 전용 사업 신호를 제거
- 사업보고서/분기보고서 비교 시 공통 핵심 사업과 전략 신호를 분리

### 평가기

- 필수 문자열 전체 포함과 선택 문자열 중 하나 이상 포함을 구분
- 기대 질의 유형을 검사
- Close/Open 답변은 답변 본문에 접수번호가 있고 citation 객체도 존재해야 통과
- 실제 수치, 단위, 기간, 연결 기준을 골드 조건으로 강화

## 최종 결과

최종 자동평가 결과는 20/20이다.

| 유형 | 통과 | 실패 |
|---|---:|---:|
| Close | 10 | 0 |
| Open | 10 | 0 |

최종 답변도 한 건씩 직접 읽어 다음을 확인했다.

- Close 10건: 수치·단위·기간·scope·계산·접수번호가 질문과 일치
- Open 10건: 질문에서 요구한 핵심 사업·제품·서비스가 포함되고 관련 공시가 표시됨
- NAVER 보고서 비교에서 자동차 산업 키워드 오탐이 제거됨
- 정보가 없는 값을 다른 전체 수치로 대체하거나 Context 밖 수치를 생성하지 않음

NAVER 전년 동기 영업수익은 서비스별 표의 반올림된 부문 합계가
`2,526,054백만원`인 반면 연결 손익계산서의 정확한 금액은
`2,526,055,415,876원`, 요약연결재무정보의 반올림 총계는
`2,526,055백만원`이다. 전체 연결 영업수익 비교이므로 더 정밀한 연결재무제표 총계를
우선하여 증가액을 `260,727,936,031원`, 증가율을 `10.32%`로 확정했다.

## 실행 명령

```bash
.venv/bin/python -m eval.evaluate_manual_qa \
  --db outputs/disclosures.db \
  --questions eval/generated_qa_questions.jsonl \
  --output eval/generated_qa_results.json
```

전체 단위 테스트:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

## 남은 한계

- Open 답변은 HyperCLOVA 연동 전이므로 공시 문장을 압축한 extractive 방식이다.
- 사업 변화의 `추가 강조`와 `강조 감소`는 사업 중단·신규 진출 판정이 아니라
  구조화된 사업 주제와 표현 출현의 차이다.
- 추가 산업·기업·기간/출처 충돌·정보 한계는 `cross_industry_audit_questions.jsonl` 40문항으로 확장했지만, 향후 실제 평가 오류는 계속 회귀셋에 추가해야 한다.
