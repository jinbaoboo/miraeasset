# Manual QA 적용 결과와 현재 개발 수준

## 적용 범위

`eval/manual_qa_questions.jsonl`에 수동 작성 질문 25개를 회귀 평가셋으로 편입했다.
`eval/evaluate_manual_qa.py`는 실제 `DisclosureAgent`를 LLM 없이 실행하고 다음을 검사한다.

- 기대 회사·공시·정정 상태·핵심 값이 검색 근거에 포함되는지
- 기대 문구가 답변에 포함되는지
- 금지 문구나 잘못된 부문 값이 답변에 포함되지 않는지
- 최종 guardrail action이 `allow`, `limit`, `clarify` 중 안전한 상태인지

최신 결과는 `eval/manual_qa_results.json`에 저장되며 25/25를 통과했다.

## 이번 질문셋으로 보완한 기능

- `네이버 → NAVER`, `JYP → JYP Ent`, `엔씨소프트 → NC` 기업 별칭 인식
- `영업수익`을 매출액 동의어로 처리하고 인접 표의 누락 단위 복원
- 차량부문처럼 행의 부문명과 옆 셀의 지표명이 결합된 segment metric 추출
- 화성기지처럼 세부 차원 근거가 없을 때 연결 전체 매출로 대체하지 않고 `limit`
- 다기업 매출·영업이익 비교에서 지표명·양사 값·단위·승자를 함께 표시
- 전년 동기 비교에서 기준연도별 호환 가능한 셀을 선택해 결정론적으로 증감률 계산
- 사업내용 질문은 `II. 사업의 내용`으로 제한하고 제품·서비스/사업개요 제목을 우선
- 같은 연도의 분기보고서와 사업보고서를 공통 사업 분류로 비교
- 정정 context에 원공시/정정공시 상태를 모두 명시

## 현재 완료 수준

### 완료

- 전체 제공 공시 4,204건 parser·구조화 DB
- 정기·주요사항·거래소·지분공시 통합 검색
- 회사·기간·공시유형 metadata filtering
- 주요 재무지표, 부문 매출, 투자계획, 증감률, 기업 비교의 결정론적 수치 처리
- 자금조달·계약·정정 lifecycle
- 사업내용 검색과 연도/보고서 유형 비교
- 근거 citation, claim/calculation 검증, 정보한계·역질문·보안 guardrail
- Swagger API와 자동 회귀 평가

### 부분 완료

- 일반 사업내용 답변은 올바른 섹션을 찾지만 현재는 extractive 요약이 중심이다.
- 사업 변화는 사전 정의된 사업 신호의 등장·강조 차이를 비교하며 완전한 의미 변화 분석은 아니다.
- 부문표의 연결/별도 표기가 원문에 없으면 `unknown`을 유지한다.
- 계약·자금조달의 “없음”은 제공 코퍼스 검색 범위 내 결론이며 법적 부존재 단정이 아니다.
- 수동 QA 중 일부는 기대 답변값 없이 회사·근거 존재만 검사하므로 25/25가 모든 문장 품질을 보장하지 않는다.

### 아직 남은 핵심

1. HyperCLOVA 실제 endpoint/key 연동 및 grounded generation 통합 시험
2. 개방형 사업 답변의 요구사항별 요약 형식과 claim 단위 citation 강화
3. 더 많은 기업·부문·사업장 표현을 포함한 수동 gold 정답 확장
4. 정답 수치·허용오차·scope를 명시한 평가 라벨과 오류 분석 dashboard
5. 동시 요청, timeout, 장애 fallback, API 보안·부하 시험

따라서 현재 상태는 “근거 검색·정형 수치·비교·lifecycle·안전한 한계 대응이 가능한
HyperCLOVA 연동 전 Agent” 단계다. 제출 수준의 자연스러운 개방형 서술은 HyperCLOVA 연동과
추가 정답 라벨링 이후가 마지막 주요 단계다.
