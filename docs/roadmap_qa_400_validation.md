# 발전 로드맵 1~4단계 QA 400문항 실제 API 검증

작성·최종 검증일: 2026-09-04

## 범위와 원칙

`docs/development_roadmap.md`의 우선순위 1~4를 각각 독립적인 100문항 세트로 구현했다.
각 세트는 `close` 50개와 `open` 50개이며, 생성기는 100개 문장의 고유성과 기존 질문 파일과의
완전 일치가 없음을 검사한다. 정답 조건은 실행 결과에 맞춰 완화하지 않고 회사·연도·질문 유형,
수치 허용오차, 단위, scope, 필수 문서, citation 필드, 답변 가능성, 검증 action을 독립 판정한다.

평가는 파이썬 내부 함수를 직접 호출한 것이 아니라 실행 중인 FastAPI의 `GET /answer`에
`use_llm=false`, `debug=true`로 실제 HTTP 요청을 전송했다. 질문별 응답·접수번호·검사 결과와
지연시간은 각 결과 JSON에 보존한다.

## 질문 세트

| 단계 | 파일 | 주요 검증 내용 |
|---|---|---|
| 1. 기간·정정·lifecycle | `lifecycle_qa_100_questions.jsonl` | 원본/정정/현재값, 계약 해지 연결, 자금조달 결정과 실제 완료 구분 |
| 2. 복합 계산 | `composite_calculation_qa_100_questions.jsonl` | 복수 지표, 증감액·증감률, 이익률, 기업 차이, CAPEX+투자방향 subtask |
| 3. 답변불가·보안 | `unanswerable_security_qa_100_questions.jsonl` | 추천·뉴스 제한, 필수 slot 역질문, prompt injection·secret 우회 차단 |
| 4. 오타·장문·구어체 | `noisy_language_qa_100_questions.jsonl` | 한 글자 오타, 공백, 종목코드, 축약어, 장문 배경 속 핵심 조건 복원 |

## 최초 실행과 개선

| 단계 | 최초 실제 HTTP 결과 | 발견·개선한 핵심 문제 |
|---|---:|---|
| 기간·정정·lifecycle | 66/100 | 정정 접수연도와 대상 사업연도 분리, 원공시/정정본 표현, 자금조달 결정·완료 상태 분기 |
| 복합 계산 | 78/100 | `복합계산`의 `합계` 오인 제거, 숫자형 각주 정리, 감소액 양의 크기 표기 |
| 답변불가·보안 | 90/100 | NFKC·제로폭·공백·하이픈을 정규화한 보안 패턴 탐지, 모호 수익률 명세 교정 |
| 오타·장문·구어체 | 60/100 | 검증된 회사 오타 별칭, `영업익/영업익률`, 구어체 사업질문, 띄어 쓴 보고서·계약 필터 지원 |

정정 응답은 질문의 보고서 subtype과 계약 종류로 체인을 좁히고, 긴 정정 원문은 앞뒤 근거를
보존한 채 압축한다. 자금조달 결정 질문에는 완료자료 부재를 답변불가 문구로 붙이지 않으며,
실제 납입완료 질문에서만 명시적인 한계를 반환한다.

## 복합 질문 성능 최적화

프로파일링 결과, 정형 재무 셀만으로 계산 답변과 접수번호를 만들 수 있는 하위 질문도 FTS를
추가 실행하면서 전체 시간의 대부분을 소비했다. 계산·정형 템플릿·전용 lifecycle 답변이 준비된
경우 FTS를 생략하고, 복합 계획 단계에서 이미 분석한 하위 질문 plan도 재사용하도록 변경했다.
근거 셀과 citation은 그대로 유지하며 서술형 일반 질문은 기존 FTS 경로를 계속 사용한다.

동일한 실제 HTTP 100문항(`workers=4`)을 전후 비교한 결과는 다음과 같다.

| 측정값 | 개선 전 | 개선 후 | 단축률 |
|---|---:|---:|---:|
| 통과 | 100/100 | 100/100 | 정확도 유지 |
| median | 11,507.47 ms | 129.42 ms | 98.88% |
| p95 | 27,431.07 ms | 577.05 ms | 97.90% |
| p99 | 36,903.95 ms | 614.83 ms | 98.33% |
| max | 36,917.01 ms | 618.82 ms | 98.32% |

평가기는 이제 모든 수동 QA 실행 결과에 nearest-rank 방식의 p95와 p99를 함께 저장한다.
단위 테스트 134개도 전부 통과해 일반 검색·계산·인용·보안 경로의 회귀가 없음을 확인했다.

## 재현

API 서버를 먼저 실행한 뒤 다음 명령을 사용한다.

```bash
DISCLOSURE_DB=outputs/disclosures.db \
  .venv/bin/uvicorn src.api.app:app --host 127.0.0.1 --port 8000 --workers 4

make eval-roadmap-http \
  PYTHON=.venv/bin/python \
  BASE_URL=http://127.0.0.1:8000
```

개별 실행은 `eval-lifecycle-http`, `eval-composite-http`, `eval-safety-http`,
`eval-noisy-http` target을 사용한다. DB는 읽기 전용 검색 대상으로 사용되며 결과 JSON에는
원문 코퍼스나 secret을 저장하지 않는다.
